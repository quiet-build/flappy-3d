# Flappy 3D

A 3D Flappy Bird-style PWA built with Babylon.js 9, TypeScript and Vite, with Preact overlays, XState, GSAP and Howler. The standalone build includes a service worker; Mini Arcade loads the native `pma-flappy` component. See [SOURCE.md](SOURCE.md) for current ownership.

**Play:** https://playminiarcade.com/game/flappy

**Standalone:** https://flappy-3d.pages.dev/

Current documentation checked 2026-10-02 against `549b6b2`, the local workflow,
and the matching remote-ref and live route/component snapshots from this audit.
The following v1.0/v1.1 notes are historical (April–May 2026, before the
2026-05-21 Babylon rebuild); their bundle sizes and acceptance claims are not
current measurements.

## Historical v1.1 — Beauty Pass (April–May 2026)

- Title screen comes alive: bird hover-bobs, demo pipes scroll past, logo letter-stagger entrance, "Tap to start" pulses
- In-game juice: `+1` score popups, milestone celebrations at 10/25/50 (gold burst + flash), optional flap trail (Settings), 4-color pipe cycling
- Glass UI: Press Start 2P arcade font on headings, `backdrop-filter` blur on overlays, gradient buttons with hover/active depth, 2-layer focus ring
- Every motion effect respects `prefers-reduced-motion` (OS) and the in-game motion toggle
- Bundle: 196KB / 250KB gzipped

## Historical v1.0 — Core Game (April–May 2026)

- Endless Flappy Bird loop: tap/click/spacebar to flap, gravity falls, pipes scroll, score on pass, die on contact
- Cel-shaded toon materials, post-processing (bloom + vignette) gated on desktop / hi-tier mobile
- 5 screens (Title, HUD, Pause, GameOver, Settings) with leaderboard + persistence
- PWA installable, offline play, Lighthouse PWA 1.00, iOS Safari audio unlock
- Accessibility: keyboard nav (Space/Enter/Esc/Tab), focus rings, ARIA-live score, colorblind palette toggle, motion-reduce override
- xstate v5 state machine, GSAP juice (squash, screen shake, particles), Howler audio with WebAudio synth fallback

## Bundle Budget

Production JS bundle must stay ≤ 600 KB gzipped (`scripts/bundle-check.sh`; budget raised for the 2026-05-21 Babylon rebuild).

Local audit at `549b6b2` on 2026-10-02: **533.96 KB gzip**, within the 600 KB budget. This build measurement does not establish device frame rate.

### Check the bundle size

```bash
pnpm --ignore-workspace build
bash scripts/bundle-check.sh
```

The build type-checks TypeScript and generates `dist/`; the size script then:
- Gzips `dist/assets/*.js` and `dist/component.js` when present
- Compares total gzip bytes against the 614,400-byte (600 KB) limit
- Exits non-zero if the limit is exceeded

### Inspect bundle composition

After any build, open `dist/stats.html` in a browser to see the interactive treemap (generated by `rollup-plugin-visualizer`). Large chunks to watch:
- `@babylonjs/core` — use deep module imports as in `src/render/createEngine.ts`; avoid importing the package barrel
- `gsap` — ~28 KB gzip (core only)
- `howler` — ~15 KB gzip
- `preact` — ~4.7 KB gzip

## Performance Testing

PERF-03: Sustained 60fps on iPhone 12 / Pixel 6 class device during normal play.

This is a **manual test** — no automated gate exists for frame rate on real hardware.

### Procedure (run before each release)

1. **Build and serve:**
   ```bash
   pnpm --ignore-workspace build
   pnpm --ignore-workspace preview --host 127.0.0.1 --port 5000
   ```
   Open `http://127.0.0.1:5000/flappy-3d/` (the default build base), or test an already published CI build at the play link above.

2. **On a mid-tier mobile device** (iPhone 12, Pixel 6, or similar — NOT an emulator):
   - Open in Chrome for Android or Safari on iOS
   - Open **DevTools** (Android: `chrome://inspect`, iOS: Safari > Develop menu)
   - Navigate to **Performance** panel → enable **FPS Meter** overlay

3. **Test scenario:**
   - Start a game run
   - Let 20–30 pipes pass (score ≥ 20 so difficulty has ramped)
   - Confirm FPS stays ≥ 58 fps throughout; brief dips to 55 on pipe spawn are acceptable

4. **If FPS drops below 55:**
   - Check the resolved quality tier in `src/render/createPipeline.ts`: auto selects high for non-mobile devices with ≥8 logical cores, medium for ≥4, otherwise low
   - Low quality returns no Babylon rendering pipeline; medium enables bloom/FXAA, and high also enables vignette
   - Reduce `POOL_SIZE` or review particle count if allocations are occurring during gameplay

5. **Record a dated result** in the current verified-state section of `.planning/STATE.md`; leave the historical metrics unchanged.

## Hardening verification

Run these checks before tagging a release. Each maps to a Phase 5 Success Criterion.

### SC-1: Memory stability (PERF-05)

1. Open the local DEV build in Chrome desktop (`pnpm --ignore-workspace dev`)
2. Open DevTools → Console
3. Play 10 death + restart cycles
4. Observe `[mem probe] round=N meshes=X` log lines (DEV build only)
5. **Pass:** the Babylon mesh count plateaus — no consistent growth across rounds

Alternate (any browser): DevTools → Memory → take Heap Snapshot before and after 10 rounds. `WebGLBuffer` count should not grow.

### SC-2: iOS audio — real device (AUD-01, AUD-02)

1. Open https://playminiarcade.com/game/flappy in Safari on a real iOS device (iOS 16+)
2. Tap the screen to start a game
3. Confirm flap, score, and death sounds play immediately (not synth oscillators)
4. In Safari Web Inspector (Mac → Develop menu → your device), run: `Howler.ctx.state` — expected: `"running"`
5. **Ringer ON:** all audio plays normally
6. **Ringer OFF (silent switch):** audio is silenced by iOS — this is expected behaviour, not a bug. The Settings modal documents this.
7. **Pass:** `Howler.ctx.state === 'running'` after first tap; SFX are recognisably flap/score/death sounds

### SC-3: Tab-blur pause/resume

1. Open the game and start a round
2. Switch to a different tab (or press Cmd+H on mobile to background the browser)
3. **Expected:** music stops immediately; game transitions to paused state
4. Return to the tab
5. **Expected:** Pause screen is shown; score is preserved
6. Tap RESUME
7. **Expected:** music resumes; game continues
8. **Pass:** All three steps confirmed correct. No music ghost-playing after tab-switch.

### SC-4: No stopped-actor warnings, no listener accumulation

1. Open https://playminiarcade.com/game/flappy in Chrome
2. Open DevTools Console (filter: Warnings + Errors)
3. Play 20 death + restart cycles
4. **Pass:** Zero "Event sent to stopped actor" warnings

Listener stability check (Chrome only):
1. After page load (before any play): `Object.values(getEventListeners(window)).flat().length` — record baseline
2. After 10 restart cycles: run same command
3. **Pass:** Count is identical (or within ±1 for browser internals)

## Deployment

Production publication is CI-only. `.github/workflows/deploy.yml` runs on main
pushes and manual Actions dispatches. It calls the pinned
`quiet-build/.github` arcade-component workflow at
`d555c9216c192be3b50cf415686981099d5c6f1d`, targeting R2 game channel
`flappy` and retaining GitHub Pages support with `pages-base: /flappy-3d/`.
Cloudflare publication now uses complete immutable R2 versions.

The caller requires redirect and gameplay checks before build, component and
standalone cream-UI/side-camera checks after build, the 600 KB bundle gate and a
0.9 Lighthouse PWA gate. These configured gates are not a claim that this
2026-10-02 source audit reran browser or hosted CI checks. Cloudflare credentials
belong in `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repository secrets.

`vite.config.ts` uses `VITE_BASE` for both asset base and PWA start URL/scope:
`/flappy-3d/` by default for GitHub Pages, `./` for the R2 build. The
R2 target is `https://assets.playminiarcade.com/channels/flappy.js`; the production portal keeps its previous Pages entry until CDN verification passes in CI. The 2026-10-02 live snapshot returned 200 for the portal route and component with
JavaScript/CORS headers; this does not prove physical-device gameplay.

For local preview, use the build/preview commands above. Do not publish from a
workstation or replace the existing CI with a dashboard/manual upload.
